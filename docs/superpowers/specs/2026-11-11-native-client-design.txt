OpenDLSS-NR Linux 原生渲染客户端设计
日期：2026-11-11
状态：用户已确认，正在实施；实际 GPU NR 验收需满足驱动能力。

用户目标
实现可在本机使用的原生渲染客户端，导入 GLB，并逐帧执行 OpenDLSS-NR 神经渲染。
使用已经修复的 test-fixed.glb 验证模型导入、正常遮挡和 NR 效果。
保留上游 Tensor Core 快速路径，避免使用浏览器的通用计算内核替代。

已经确认的选择
用户选择：采用上游快速内核，并愿意升级所需的 NVIDIA 驱动、重启后验收。
平台按现有机器确定：Linux x86_64、X11、NVIDIA RTX 4080 SUPER。
驱动升级和重启由用户单独执行，本项目不会自动更换系统驱动。

方案比较
A. Linux 移植现有原生客户端，保留快速 PTX/FP8 内核（已选择）。
   优点：复用现有 Filament 场景渲染、运动向量、时间历史和同一 Vulkan 队列中的 NR。
   代价：适配 Linux 构建；需要驱动支持上游必需的 Vulkan 扩展。
B. 保留 580 驱动，扩展 PTX 内核覆盖并替换 FP8 GLSL 运算（未选择）。
   代价：修改网络执行路径，增加逐算子一致性验证与性能验证工作。
浏览器通用计算版本不作为实现方案，因为不满足用户选择的原生性能目标。

实现基础
OpenDLSS-NR，提交 9d08f4184bbcb9d858e2fb7a7834ec0837a9d2f1，保留 MIT 许可证和 NOTICE。
渲染器复用其 Filament v1.77.0 补丁与 SDL2/X11 窗口、gltfio 导入器。
网络保持 310.8.0 对应的 71 个块；不将最新版其他结构的模型假作兼容模型。
使用 VK_NV_cuda_kernel_launch 加载上游生成的 PTX，保留 FP8 Tensor Core 矩阵计算。
GLSL 操作保留上游数值行为，不用网页内核、合成权重或普通着色器替代快速路径。

数据流程
GLB/glTF -> Filament 场景、材质、相机 -> 颜色代理、运动向量
-> 同一 Vulkan 设备中的 NR 预处理、网络、时间合成 -> 显示。
推理不按帧经过 CPU 图像下载与重新上传；截图仅在主动保存或验证时读回。
模型切换、分辨率变化和时间历史失效时重建或重置相应资源。

首版交互（实现者的建议）
1. 通过启动参数、拖放 GLB 或输入本地文件路径加载模型；glTF 可读取相邻纹理和缓冲区。
2. 轨道旋转、缩放、平移、重新取景；默认打开测试人物的上半身视角。
3. NR 开关、时间历史开关、重置历史；使用真实逐帧网络输出。
4. 支持 512x512、1024x1024 和自定义分辨率，实际输出与所选分辨率一致。
5. 保留上游神经渲染参数和场景曝光、照明控制。
6. 分别显示网络 GPU 耗时与整帧时间/FPS，并显示 NR 是否真正启用。
7. 只在用户主动操作或验证模式下保存帧，不按帧进行 PNG 编码。
首版不是完整资产编辑器，不加入建模、材质编辑或时间线编辑功能。

权重准备
已确认可用文件：
<RTX Remix 1.6.1 解压目录>/nvngx_dlssnr.dll
SHA256：2bc19bc09a7b89dd44f73e2ac0108fcc586e2154bdd0830f242f4f040e28789f
通过已有静态提取器读取 PE 资源，生成原生 nr::Model 需要的 manifest.json 和 model/stage-N.bin。
提取过程不执行 DLL；校验 71 个网络块、153 个张量和阶段文件哈希。
本地权重与应用分开存放，不发布到外部服务。

测试模型适配
原文件：用户提供的 test.glb。
材质修复版：outputs/test-fixed.glb；Face、Body 为 OPAQUE，其他真实透明材质保留。
该文件的单个 skin 声明 1185 个骨骼；脸部有效调色板为 512，超过 Filament 的 256 上限。
该文件没有动画或 morph，因此另生成静态预览副本，正确烘焙当前蒙皮位置和法线。
不能直接删除蒙皮数据：该模型的绑定变换含约 100 倍缩放，直接删除会改变尺寸。
验证烘焙前后的世界空间位置和法线，保留原始文件、材质修复版和所有贴图。
普通兼容 GLB 的动画继续使用上游路径；超过 256 骨骼的动画资产给出明确错误，
首版不静默静态化动画，也不实现通用骨骼调色板切分器。
透明头发和睫毛沿用上游材质能力；上游透明物体的独立运动向量限制要在说明中保留。

Linux 构建和交付
实施后源码及启动入口放在 outputs/opendlss-nr-client。
工作目录中的构建缓存、Filament 源码和编译器依赖放在 work/，避免混入交付文件。
补充可复现的 Linux 构建脚本和依赖检测；优先使用用户目录内的工具链。
上游要求的现代 Vulkan-Headers、volk、glslang 和 Filament 编译器依赖按版本固定。
不自动运行 sudo、不全局替换编译器或图形驱动；确需系统依赖时列出准确缺项。
最终启动脚本能够找到应用资源、PTX/SPIR-V、权重和测试模型，不依赖当前工作目录。

启动检查
核实实际选中的 NVIDIA 设备和 VK_KHR_cooperative_matrix、VK_NV_cooperative_matrix2、
VK_EXT_shader_float8、VK_NV_cuda_kernel_launch 及实际请求的特性。
当前本机 580.178.04 不暴露 VK_EXT_shader_float8，不能完成上游 NR 运行验收。
缺失时显示具体设备、驱动、缺失能力和后续操作；不悄悄退回浏览器、CPU 或 NR 关闭状态。
升级驱动后重新探测，不能仅根据驱动版本号推断满足要求。

验证与验收
1. Linux 原生源码和着色器可构建，启动入口可检测依赖与资源。
2. 静态提取后的权重通过结构、长度、哈希和原生加载检查。
3. 测试模型烘焙后通过 glTF 校验，世界空间位置误差不超过 1e-5。
4. 在满足扩展的驱动上，实际启动原生客户端并导入测试模型，检查眼睛、头发和颈部。
5. 在同一相机下验证 NR 开/关输出不同、输出有限且可保存，时间历史能够重置。
6. 1024x1024 下先预热，再测至少 120 帧的网络 GPU 时间与整帧中位数、P95。
7. 记录 GPU、驱动、分辨率、网络后端和帧数，目标是开启 NR 后整帧中位数低于 33.3 ms。
   这是待本机测量的验收目标，不把 RTX 5080 的 3.10 ms 当作本机成绩。
8. 另验模型重新加载、调整分辨率、缺失权重和不兼容资产的错误路径。

完成边界
代码编译通过不等于 NR 已运行；NR 运行不等于已经达到目标帧率。
若驱动升级前完成构建，明确标记“待驱动升级后的 GPU 运行验收”，不报告虚假帧率。
原有 GLB、DLL、浏览器项目和系统驱动保持原样。
